## Breaking Change Analysis

### SEVERITY: COMPILE FAILURE — Must fix before building

---

#### 1. Deprecated RGB Keycodes Removed (0.30)
**Changelog:** [0.30 — Removal of deprecated RGB and Mouse keycodes](https://docs.qmk.fm/ChangeLog/20250831)
**Impact:** 57 files across keymaps and shared source

The `RGB_xxx` style keycodes were deprecated in 0.27 and **removed** in 0.30. They must be replaced with `UG_xxx` (underglow/rgblight) equivalents. If a board uses RGB Matrix *only* (not rgblight), consider `RM_xxx` keycodes instead, but `UG_xxx` controls both simultaneously and is the safest 1:1 migration.

| Old Keycode | New Keycode |
|-------------|-------------|
| `RGB_TOG` | `UG_TOGG` |
| `RGB_MOD` | `UG_NEXT` |
| `RGB_RMOD` | `UG_PREV` |
| `RGB_HUI` | `UG_HUEU` |
| `RGB_HUD` | `UG_HUED` |
| `RGB_SAI` | `UG_SATU` |
| `RGB_SAD` | `UG_SATD` |
| `RGB_VAI` | `UG_VALU` |
| `RGB_VAD` | `UG_VALD` |
| `RGB_SPI` | `UG_SPDU` |
| `RGB_SPD` | `UG_SPDD` |
| `RGB_MODE_PLAIN` | `UG_NEXT` (cycle to it) |
| `RGB_MODE_BREATHE` | `UG_NEXT` (cycle to it) |
| `RGB_MODE_FORWARD` | `UG_NEXT` |
| `RGB_MODE_REVERSE` | `UG_PREV` |
| `RGB_MODE_GRADIENT` | `UG_NEXT` (cycle to it) |

**Affected shared source:**
- `keyboards/fingerpunch/src/fp_encoder.c` — encoder actions reference `RGB_*`
- `keyboards/fingerpunch/src/fp_encoder.h` — `RGB_*` in defines
- `keyboards/fingerpunch/src/fp_rgb_common.c` — switch/case on `RGB_MODE_FORWARD .. RGB_MODE_GRADIENT`
- `keyboards/fingerpunch/vulpes_majora/v1/config.h` — encoder layer defines

**Affected keymaps (partial list):** virtually every `default/keymap.c` and `sadekbaroudi/keymap.c` across all boards.

#### 3. Deprecated GPIO API Removed (0.32)
**Changelog:** [0.32 — Removal of deprecated GPIO defines](https://docs.qmk.fm/ChangeLog/20260222)
**Impact:** 5 files, ~32 call sites

The Arduino-style GPIO names are removed. Replace with QMK-styled equivalents:

| Old Function | New Function |
|-------------|-------------|
| `setPinInput(pin)` | `gpio_set_pin_input(pin)` |
| `setPinInputHigh(pin)` | `gpio_set_pin_input_high(pin)` |
| `setPinInputLow(pin)` | `gpio_set_pin_input_low(pin)` |
| `setPinOutput(pin)` | `gpio_set_pin_output(pin)` |
| `setPinOutputOpenDrain(pin)` | `gpio_set_pin_output_open_drain(pin)` |
| `writePinHigh(pin)` | `gpio_write_pin_high(pin)` |
| `writePinLow(pin)` | `gpio_write_pin_low(pin)` |
| `writePin(pin, level)` | `gpio_write_pin(pin, level)` |
| `readPin(pin)` | `gpio_read_pin(pin)` |
| `togglePin(pin)` | `gpio_toggle_pin(pin)` |

**Affected files:**
- `keyboards/fingerpunch/personal/testamatta/matrix.c` — 12 occurrences
- `keyboards/fingerpunch/personal/ximi/matrix_74hc595_spi.c` — 6 occurrences
- `keyboards/fingerpunch/personal/ximihalf/matrix_74hc595_spi.c` — 6 occurrences
- `keyboards/fingerpunch/personal/zazu/zazu.c` — 2 occurrences (commented out)
- `keyboards/fingerpunch/src/fp_matrix_74hc595_spi.c` — 6 occurrences

#### 4. `encoder_update_user` / `encoder_update_kb` Removed (0.30)
**Changelog:** [0.29 — Deprecation of `encoder_update_{kb|user}`](https://docs.qmk.fm/ChangeLog/20250525), removed by 0.30
**Impact:** 7 files

These callbacks are gone. Must migrate to **encoder map** (`ENCODER_MAP_ENABLE`). The fingerpunch shared library (`fp_encoder.c`) implements `encoder_update_kb` with a rich layer-aware encoder system. This will be the most complex single migration.

**Affected files:**
- `keyboards/fingerpunch/src/fp_encoder.c` — core implementation of `encoder_update_kb`
- `keyboards/fingerpunch/personal/klor/keymaps/*/keymap.c` — 4 keymap files with `encoder_update_user`
- `keyboards/fingerpunch/README.md` — documentation

---

#### 5. `promicro_rp2040` Converter Renamed (0.26)
**Changelog:** [0.26 — SparkFun Pro Micro RP2040 converter renamed](https://docs.qmk.fm/ChangeLog/20240825)
**Impact:** 2 files directly + 6 files with stale `#ifdef` guards

The converter `promicro_rp2040` was renamed to `sparkfun_rp2040`. The clone boards (like the one fingerpunch uses) should use `rp2040_ce` instead.

**Affected files:**
- `keyboards/fingerpunch/personal/klor/2040/rules.mk` — `CONVERT_TO = promicro_rp2040`
- `keyboards/fingerpunch/personal/klor/2040/readme.md` — documents old name
- Multiple `config.h` / `mcuconf.h` / `halconf.h` files with `#ifdef CONVERT_TO_PROMICRO_RP2040` guards that will silently fail

The JSON key `split.soft_serial_pin` was migrated to `split.serial.pin`.

#### 7. `MASTER_LEFT` / `SPLIT_HAND_PIN` in config.h (migrate to Data-Driven)
**Impact:** ~14 files

These should move to `split.main` in `info.json`/`keyboard.json`:
```json
{
  "split": {
    "main": "left"
  }
}
```
Or for `SPLIT_HAND_PIN`:
```json
{
  "split": {
    "main": "pin",
    "handedness": {
      "pin": "B5"
    }
  }
}
```

#### 8. `SOFT_SERIAL_PIN` / `SERIAL_USART_TX_PIN` in config.h (migrate to Data-Driven)
**Impact:** ~11 files

Should move to `split.serial.pin` in `info.json`/`keyboard.json`:
```json
{
  "split": {
    "serial": {
      "pin": "D2"
    }
  }
}
```

#### 9. `#define MATRIX_ROWS` / `#define MATRIX_COLS` in config.h (migrate to Data-Driven)
**Impact:** ~56 files

These should move to the `matrix_size` field in `keyboard.json` / `info.json`, or be derived from the `matrix_pins` definition:
```json
{
  "matrix_pins": {
    "rows": ["B1", "B2", "B3", "B4"],
    "cols": ["C1", "C2", "C3", "C4", "C5", "C6"]

}
```

#### 11. `RGB_MATRIX_LED_COUNT` in config.h (migrate to Data-Driven)

#### 12. `RGBLIGHT_LED_COUNT` / `RGBLED_NUM` in config.h (migrate to Data-Driven)
**Impact:** ~43 files

Should move to `rgblight.led_count` in `info.json`/`keyboard.json`:
```json
{
  "rgblight": {
    "led_count": 42
  }
}
```

---

#### 13. `#ifdef CONVERT_TO_PROMICRO_RP2040` Guards Are Stale
**Impact:** ~6 files

These `#ifdef` checks reference a define that no longer exists with the renamed converter. They silently skip their code blocks. Replace with `#ifdef CONVERT_TO_SPARKFUN_RP2040` or, more likely for clones, `#ifdef CONVERT_TO_RP2040_CE`.

### SEVERITY: INFORMATIONAL — Good to know, no immediate action required

---

#### 14. RGB/HSV Struct Renames (0.27)
The `RGB` struct was renamed to `rgb_t` and `HSV` to `hsv_t` in core code. The old names have backward compatibility defines, so no immediate action. Your code uses `rgblight_sethsv_noeeprom` etc. which are fine.

#### 15. VIA Keymaps Moved Out (0.26)
VIA keymaps should no longer live in `qmk_firmware`. You have some `via` keymaps under fingerpunch — these are fine for your personal fork but would be rejected from upstream.

#### 16. Key Override Signature Change (0.26)
If any fingerpunch keymaps use `key_overrides`, the signature changed from `const key_override_t **key_overrides = (const key_override_t *[]){..., NULL};` to `const key_override_t *key_overrides[] = {...};` (no NULL terminator). No matches found in fingerpunch code.

#### 17. Tap Dance State Refactor (0.31)
`action->state` is no longer embedded — use `tap_dance_get_state()` separately. No tap dance usage found in fingerpunch.

#### 18. `process_action_kb` Removed (0.30)
No usage found in fingerpunch. ✅

#### 19. `isLeftHand` Deprecated (0.32)
Should use `is_keyboard_left()` instead. No usage found in fingerpunch. ✅

#### 20. `DEFAULT_FOLDER` Removed (0.30)
No usage found in fingerpunch. ✅

#### 21. Converter Pin Compatible Updates (0.30)
Keyboards should declare `development_board` in `keyboard.json` to use converters. This is advisory for now; converters still work but may stop in a future release.
